# معمارية المرحلة 2

## تدفق الاستيعاب

```
POST /api/uploads ──► فحص الامتداد + التوقيع الفعلي + الحجم ──► قراءة كل الأوراق (worker معزول)
        │                                                          │
        │                  كشف صف العناوين + مرشحي الأعمدة (اقتراحات فقط)
        ▼                                                          ▼
  uploads · upload_sheets · raw_rows (القيم الأصلية) · data_quality_issues (FILE/MAPPING)
        │
GET  /preview ─► معاينة (مع حجب الأعمدة الحساسة)
POST /mapping?dryRun=true ─► تحقق + سجلات مطبّعة (بدون حفظ)
POST /mapping ─► يحفظ نسخة ربط جديدة (column_mappings.version) — الحقول غير الواثقة تتطلب تأكيدًا صريحًا
POST /process ─► معاملة واحدة: تطبيع → جودة → عمر → مقارنة → shipment_snapshots + snapshot_comparisons
```

## قرارات الأعمال المعتمدة وكيف طُبّقت

| القرار | التطبيق |
| --- | --- |
| الحد الأقصى للعمر 15 يومًا لكل الأنواع، والحرج أكثر من 25 | `settings.aging` (قابلة للتعديل). **15 يومًا بالضبط لا يزال ضمن المسموح**؛ الحرج `> 25`. |
| عمر الشحنة = `snapshot_date − تاريخ الإنشاء` بالأيام التقويمية، ونفس اليوم = 0 | `engine/aging.ts` (حساب على UTC لأيام تقويمية، مستقل عن التوقيت الصيفي). |
| فئات العمر 0–3 / 4–7 / 8–15 / 16–25 / >25 | `bucketBounds=[3,7,15,25]` من الإعدادات. |
| عمر الحالة الحالية | تاريخ دخول حالة صالح من الملف ← وإلا مدة ملاحَظة بين لقطتين متتاليتين بنفس الحالة ← وإلا `UNKNOWN — INSUFFICIENT HISTORICAL DATA`. لا يُفترض تاريخ دخول أبدًا. |
| عمر آخر تحديث | يُحسب فقط من تاريخ آخر تحديث صالح وغير مستقبلي، ومنفصل تمامًا عن العمرين الآخرين. |
| العهدة | اسم الموظف هو الدليل الأساسي. غيابه ⇒ `MISSING_EMPLOYEE` (تحذير يحتاج مراجعة، تصنيف «قواعد العمل»). لا يُعتبر الفرع دليل عهدة، ولا تُنشأ نتائج مخالفة/تقصير. |

### دلالات عمر الحالة (مهم للتفسير)
- أول لقطة: كل الأعمار `UNKNOWN` ما لم يُوجد تاريخ دخول الحالة في الملف.
- المدة «الملاحَظة» **حد أدنى**: الحالة قد تكون أقدم من أول ملاحظة لها.
- تغيّر الحالة، أو غياب الشحنة ثم عودتها، يعيد تشغيل العدّ ويصبح العمر `UNKNOWN` في ذلك الجرد.
- الفاصل الزمني بين الجردين يدخل في الحساب (الفرق بين تواريخ اللقطات) ويصدر تحذير `SNAPSHOT_GAP` إن تجاوز يومًا.

## المقارنة بين اللقطات
- المفتاح: رقم الشحنة بعد التطبيع (أرقام عربية→لاتينية، حروف كبيرة، إزالة المسافات).
- `CONTINUED` موجودة في الجردين؛ ومعها `STATUS_CHANGED` / `BRANCH_CHANGED` / `EMPLOYEE_CHANGED` عند تغيّر القيمة. `NEW` لم تُرَ من قبل. `REAPPEARED` غابت في الجرد السابق وظهرت في جرد أقدم. `DISAPPEARED` كانت في السابق وغابت اليوم.
- **لا استنتاج لنتيجة نهائية:** الاختفاء ليس تسليمًا، وتغيّر الحالة ليس نجاح إجراء.
- الحالات والفروع تُقارَن بمفتاح معياري: مرادفات قاموس الحالات وأسماء الفروع البديلة تُعتبر الشيء نفسه (`جديد` = `New`، `Cairo` = `القاهرة`). الموظفون يُقارَنون بالاسم بعد توحيد الحروف العربية فقط.
- تُقارَن كل لقطة بآخر لقطة معتمدة بتاريخ أسبق. تاريخ غير متزايد ⇒ لا مقارنة وتحذير `NON_INCREASING_DATES`.

## إصدارات اللقطات
- `(snapshot_date, version)` فريد. رفع جرد لتاريخ موجود يتطلب `replaceExisting=true` وينشئ **نسخة جديدة** تُشير إلى السابقة (`supersedes_snapshot_id`)؛ القديمة لا تُعدَّل.
- إدراج جرد بتاريخ أقدم من آخر جرد محفوظ مرفوض (`SNAPSHOT_OUT_OF_ORDER`) حتى لا تتغير مقارنات محفوظة.

## تصنيف المشكلات
| التصنيف | الأمثلة |
| --- | --- |
| `FILE_LEVEL` | امتداد/محتوى غير صالح، حجم، ملف تالف، ورقة فارغة |
| `ROW_LEVEL` | رقم شحنة مفقود (يُرفض الصف)، حالة/فرع/تاريخ إنشاء مفقود، تاريخ غير صالح |
| `BUSINESS_WARNING` | موظف مفقود/مجهول، تاريخ مستقبلي، مكرر، حالة/فرع غير معروف، تعارض تواريخ |
| `MAPPING_WARNING` | عمود ملتبس/منخفض الثقة، عمود مطلوب ناقص، تعارض أعمدة |

كل مشكلة: رقم، ورقة، صف إكسل، حقل، قيمة أصلية، تصنيف، خطورة (ERROR/WARNING/INFO)، شرح، تصحيح مقترح.
