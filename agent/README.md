# ARRIVE AI Inventory & Audit Agent — المرحلة 2: الأساس ومحرك الاستيعاب

مشروع مستقل تمامًا داخل `/agent`. **لا يعدّل ولا يعتمد على** لوحات المستودع القائمة (`index.html`، `miss-pickup/`، `apps-script/`).
راجع `docs/BASELINE.md` لخط الأساس وبصمات الملفات القائمة.

> المرحلة 2 تغطي: رفع Excel/CSV، اكتشاف وربط الأعمدة (عربي/إنجليزي)، التطبيع، فحوص جودة البيانات، اللقطات اليومية التاريخية، ومقارنتها.
> **لا يوجد** في هذه المرحلة: مساعد الذكاء الاصطناعي، لوحة الإدارة النهائية، كشف الشذوذ، محرك قواعد التدقيق الكامل، أو المصادقة الفعلية.

## الهيكل

```
agent/
├─ apps/
│  ├─ api/        Fastify + TypeScript (واجهة REST، خدمات الرفع والمعالجة)
│  └─ web/        React + Vite + MUI (RTL، خط Cairo) — واجهة اختبار المرحلة 2 (6 صفحات)
├─ packages/
│  ├─ shared/     أنواع وثوابت مشتركة (بلا اعتماديات تشغيل)
│  ├─ engine/     محرك حتمي نقي: قراءة الملفات، الاكتشاف، الربط، التطبيع، الجودة، الأعمار، المقارنة (بلا قاعدة بيانات وبلا AI)
│  ├─ database/   PostgreSQL: migrations (up/down) و seeds ومستودعات الاستعلام
│  └─ ai/         حاجز فارغ للمرحلة 5 (لا تنفيذ)
├─ tests/
│  ├─ fixtures/   ملفات اختبار مولّدة + expected.ts (نتائج محسوبة يدويًا)
│  ├─ integration/ اختبارات تكاملية (API + قاعدة بيانات حقيقية)
│  ├─ support/    harness الاختبار
│  └─ e2e/        اختبار متصفح (Playwright المثبّت في البيئة)
├─ docs/          BASELINE · ARCHITECTURE · API · PHASE2_REPORT
├─ .env.example · package.json (npm workspaces) · README.md
```

npm workspaces: كل الاعتماديات داخل `/agent` فقط. لا `package.json` ولا `node_modules` في جذر المستودع.

## التشغيل المحلي

المتطلبات: Node ≥ 22، PostgreSQL ≥ 14.

```bash
cd agent
npm install
cp .env.example .env            # ثم عدّل كلمة مرور قاعدة البيانات
export DATABASE_URL=postgres://arrive:CHANGE_ME@127.0.0.1:5432/arrive_audit
npm run db:migrate && npm run db:seed
npm run build                    # يبني الحزم والـ API والواجهة
node apps/api/dist/server.js     # الـ API على :3001
npm run dev --workspace @arrive/web   # الواجهة على :5173 (تمرّر /api إلى :3001)
```

### الأوامر

| الأمر | الوظيفة |
| --- | --- |
| `npm test` | كل الاختبارات (تحتاج PostgreSQL، انظر أدناه) |
| `npm run test:coverage` | الاختبارات مع قياس التغطية |
| `npm run lint` · `npm run typecheck` | ESLint · فحص الأنواع (الحزم + الواجهة) |
| `npm run build` | بناء كامل (ينسخ ملف عامل قراءة الجداول إلى `dist`) |
| `npm run db:migrate` · `db:status` · `db:seed` | الهجرات وحالتها وبيانات المرجع |
| `npm run db:rollback -- --steps=1` | التراجع (انظر استراتيجية التراجع) |
| `npm run fixtures` | إعادة توليد ملفات الاختبار |
| `node tests/e2e/ui-smoke.mjs` | اختبار المتصفح ضد نظام يعمل (انظر الملف) |

**قاعدة بيانات الاختبار:** الاختبارات تستخدم `TEST_DATABASE_URL` وتفرّغ مخططها بالكامل عند كل تشغيل. القيمة الافتراضية
`postgres://arrive:arrive_dev@127.0.0.1:5432/arrive_audit_test` لقاعدة محلية مؤقتة فقط؛ **لا تُوجّهها أبدًا إلى قاعدة فيها بيانات حقيقية.**

## استراتيجية التراجع عن الهجرات

- كل `NNNN_name.up.sql` له `NNNN_name.down.sql` (يُرفض التحميل إن غاب).
- كل هجرة تُنفَّذ في معاملة واحدة ويُسجَّل `checksum` لها؛ تعديل هجرة مطبّقة يوقف التشغيل.
- هجرات التراجع التي تُسقط جداول بيانات معلَّمة `-- destructive: true` وتُرفض ما لم يُمرَّر `--force` صراحةً.
- التراجع يتم من الأحدث إلى الأقدم، وكل خطوة معاملة مستقلة.
- في الإنتاج: خذ نسخة احتياطية قبل أي هجرة؛ التراجع بـ `--force` يحذف البيانات ولا يمكن استعادتها إلا من النسخة.

## حماية البيانات والسلامة

- **البيانات الأصلية لا تتغير:** `raw_rows` تحفظ قيم الخلايا كما قُرئت (التواريخ تبقى أرقام إكسل التسلسلية). الملف المرفوع محفوظ بالبايت نفسه تحت اسم عشوائي وبصمة SHA-256.
- **لا حذف صامت:** المكررات والصفوف الناقصة والفارغة تُسجَّل في `data_quality_issues` وتبقى في `raw_rows`. المكرر يُخزَّن ويُعلَّم، وأول ورود فقط هو «الأساسي» في المقارنات.
- **حماية على مستوى قاعدة البيانات:** triggers تمنع `UPDATE`/`DELETE` على `raw_rows` و`shipment_snapshots` و`snapshot_comparisons` وعلى اللقطات المكتملة، و`audit_log` للإلحاق فقط. الحذف مسموح فقط داخل `SET LOCAL arrive.allow_purge='on'` (للاحتفاظ بالبيانات مستقبلًا).
- **معاملة واحدة للمعالجة:** أي فشل يتراجع بالكامل (لا لقطة جزئية). الفشل يُسجَّل في `audit_log` وتصبح حالة الرفع `FAILED`.
- **عزل قراءة الجداول:** الملفات تُقرأ داخل `worker_thread` بحد ذاكرة ومهلة زمنية (انظر القيود).
- **المصادقة جاهزة معماريًا فقط:** كل طلب يمرّ عبر `Authenticator` ويحمل `req.actor`. الوضع `none` مرفوض في `production` ما لم تُمرَّر `ALLOW_UNAUTHENTICATED=true`.
- الأعمدة الحساسة (هاتف/عنوان/عميل/مبالغ…) **محجوبة في المعاينة**، ولا يُقرأ منها أي حقل في الاستيعاب.
